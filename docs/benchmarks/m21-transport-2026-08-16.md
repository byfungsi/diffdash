The gate runs 38 Core tests covering authenticated Unix-socket lifecycle, exact per-method payload
boundaries, deadlines, disconnects around a controlled acceptance boundary, scoped cancellation,
restart recovery, and pressure before running the parser and cancellation micro-fixture. The socket
pressure test holds
32 requests in handlers, verifies that further requests do not enter handlers, and verifies
disconnect interruption. A separate conservative retention model reserves one full frame per
admitted request; it is not an operating-system socket-memory measurement. The micro-fixture's
detached primitive isolates timing only; application cancellation is owned by a bounded scoped
`FiberSet`, and accepted generation workers are owned by Core's scoped `FiberMap`.

## Alternatives

| Concern | Alternatives | Selected |
| --- | --- | --- |
| Native frame/incomplete input | 256 KiB, 512 KiB, 1 MiB | 512 KiB |
| Walkthrough streaming | 64 KiB chunks with 8 acknowledgements, unary | Unary: chunk and acknowledgement limits are both zero |
| Aggregate in-flight bytes | 8 MiB, 16 MiB PRD guardrail | 16 MiB maximum |
| Concurrent requests | 16, 32, 64 | 32; one 512 KiB reservation each exactly exhausts 16 MiB |
| Caller cancellation | Interrupt every method, detach every method, method-specific | Reads interrupt; start detaches after durable acceptance; cancel is uninterruptible |

Unary transport avoids chunk reassembly, acknowledgement state, and a second application queue. The
384 KiB maximum walkthrough response leaves 131,072 bytes of frame headroom for the RPC envelope.
The selected concurrency is the largest candidate that can reserve a full frame per request without
exceeding the existing 16 MiB in-flight Core transport guardrail.

## Decision

D-01 is accepted for the inactive FUN-218 walkthrough prototype with these limits:

- 512 KiB native MessagePack incomplete-frame bound.
- 16 MiB aggregate in-flight transport guardrail.
- 32 concurrent requests, reserving at most one frame each.
- Unary walkthrough RPC only, with zero chunk and acknowledgement state.
- 384 KiB maximum walkthrough read response; request and response limits remain method-specific.
- Interruptible reads, detached post-acceptance generation, and uninterruptible cancellation.

The inactive walkthrough socket prototype enforces one 512 KiB reservation per accepted request, a
32-request aggregate ceiling, bounded encoded responses, and disconnect cleanup. The benchmark does
not activate the external Core in production. FUN-215 owns the atomic production cutover, when this
host can replace `EmbeddedCore`; FUN-254 remains responsible for renderer replay and cross-process
diagnostics. Neither follow-up may increase the 16 MiB guardrail without an RFC amendment.
